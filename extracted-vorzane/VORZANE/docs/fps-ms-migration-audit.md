# تقرير تدقيق الترحيل إلى FPS.ms

**تاريخ التدقيق:** 7 نوفمبر 2026. يضم هذا التقرير نتائج مراجعة الملفات، حقائق FPS.ms من صفحاتها الرسمية، وفحصًا محدودًا للبيانات الحية. لم يتضمن محتوى الحفظ أو بيانات تعريف اللاعب.

## ما وجدناه في المشروع

المشروع الحالي واجهة Expo Router/React Native Web باللغة العربية مع RTL وهوية فانتازيا داكنة. يتضمن شاشات المخيم والرحلات والعتاد والمهام والإعدادات، وحسابات بريد/ضيف/Google، واستيراد/تصدير للحفظ. منطق القتال والعملة والغنائم والسوق المحلي والمهام والرحلات داخل العميل؛ لا يوجد في الملفات المدققة خادم Node سلطوي أو Prisma/MariaDB أو عامل خلفي أو WebSocket.

يعتمد الحفظ الحالي على `public.player_saves` في Supabase، بسجل `game_state` من JSONB لكل `user_id` مع قيد أجنبي إلى `auth.users` وسياسات RLS خاصة بـSupabase. هذه الحماية لا تنتقل تلقائيًا إلى MariaDB. كما أن نسخة `legacy/web` تشير إلى وظائف قديمة لا ينبغي حذفها قبل جرد ميزاتها ومقارنتها بالتطبيق الحالي.

كانت صور الفئات الأربع وختم VORZANE تشير إلى مسارات `/manus-storage/async-images/`، لا إلى ملفات ضمن Git. نُقلت الصور الأصلية المتاحة إلى `public/images/characters/` بعد التحقق البصري من نوعها ومحتواها، وحُدّثت `src/game/art.ts` إلى المسارات المحلية؛ فحص الشيفرة بعد النقل لم يجد روابط مجموعة الصور القديمة. موسيقى اللعبة موجودة محليًا بالفعل، ونسختاها متطابقتان بالـSHA-256. بذلك لا تعتمد أصول الواجهة الأساسية على تخزين Manus عند بناء الواجهة الجديدة.

## حالة بيانات Supabase عند التدقيق

في فحص قراءة فقط لمشروع Supabase `incidgigfqyjbqfegukg` بتاريخ 7 نوفمبر 2026، ظهر حساب واحد في `auth.users` وصف واحد في `public.player_saves`. أكد مخطط الجدول أن `player_saves.user_id` مفتاح أساسي ومرجع أجنبي إلى `auth.users.id`، لذلك الصف مرتبط بحساب موجود. لم أقرأ البريد أو محتوى `game_state`، ولم أصدّر أو أعدّل أو أحذف أي بيانات.

هذه الأعداد لقطة وقت التدقيق وليست ضمانًا لعدم تغير البيانات لاحقًا. يجب إعادة الجرد والنسخ الاحتياطي قبل النقل الفعلي، مع مطابقة العدد والحقول والبصمات واختبار استعادة النسخة.

## متطلبات النقل

يجب أن يرسل العميل نوايا الأفعال فقط. يتحقق الخادم من الهوية والملكية والمستوى والرصيد والسعر والوقت، ويحسب المعارك والمكافآت والغنائم والتقدم. تعمل عمليات السوق والمطالبات والرحلات في معاملات ذرية مع مفاتيح idempotency وسجل تدقيق حتى لا تتكرر المكافآت أو تتجاوز الحالة القديمة الأحدث.

يحتاج مشروع FPS.ms إلى Node.js API وREST وWebSockets آمنة، وMariaDB مع Prisma ومهاجرات منظمة، ومصادقة منفصلة تربط معرّف Supabase القديم بأمان. لا يمكن نقل كلمات المرور أو الجلسات على افتراض أنها قابلة للنقل؛ يجب التحقق من نوع الحساب ومزود الدخول وآلية استرداد آمنة قبل تحويل الهوية. يجب الحفاظ على خيارات البريد وGoogle والضيف، مع بقاء النسخة القديمة صالحة للرجوع.

تُحسب الرحلات والمهام المؤقتة بوقت الخادم/UTC، وتُسوى المكافآت بعملية قابلة لإعادة التشغيل ومحمية من الصرف المكرر. يجب ألا تعتمد المعالجة على ساعة جهاز اللاعب. تستخدم WebSockets للتحديثات الحية الموثقة، مع استعادة الحالة المرجعية عبر REST عند إعادة الاتصال.

## حقائق FPS.ms الرسمية

- **Node.js hosting [1]:** يدعم Node.js managed containers عناوين HTTPS عامة وWebSockets، ويذكر Express وFastify. تُثبّت الحزم من `package.json`، وتُحقن متغيرات البيئة عند بدء الحاوية. تظهر خطط مدفوعة تشمل MariaDB ونسخة احتياطية واحدة من c.nano (256 MB RAM و500 MB SSD) بسعر معلن €0.99 شهريًا وc.micro (512 MB RAM و1 GB SSD) بسعر معلن €1.29 شهريًا. تُعرض GitHub deploys والنطاقات المخصصة كميزات Pro.
- **Managed databases [2]:** تسرد الخدمة PostgreSQL وMariaDB وValkey. الصفحة تقول إن TLS مدمج لـMariaDB وتذكر أن عملاء MariaDB يستخدمونه تلقائيًا. قاعدة البيانات حاوية مُدارة وليست VPS.
- **Container hosting [3]:** يدعم Node.js وواجهات API وخدمات الخلفية ومتغيرات البيئة وروابط عامة مع TLS. الخطط المدفوعة من 256 MB تذكر قاعدة MariaDB، وتوجد Schedules لإعادة تشغيل الخادم أو إرسال أمر مجدول.
- **حدود التحقق:** المصادر العامة التي فُحصت لا تحدد عقد `PORT` أو سلوك أمر التشغيل بدقة أو أسماء مضيف/متغيرات MariaDB أو إجراء تصدير واستعادة النسخ الاحتياطية أو health check. يجب تأكيد ذلك من حساب FPS.ms ووثائقه قبل النشر.

## حدود التنفيذ والتحويل

لا توجد صلاحية FPS.ms في هذه الجلسة، ولم يُنفذ نشر أو اختبار اتصال بقاعدة MariaDB خارجية. إعداد النشر التلقائي لـManus مفعّل، لذلك لم تُرفع تغييرات إلى `main` ولم تُحدّث نسخة Manus. لا يجوز إعلان نجاح الترحيل حتى يُختبر البناء والاتصال والمهاجرات والـhealth check، ثم تُستورد بيانات الحساب والحفظ وتُطابق وتُستعاد بنجاح في بيئة FPS.ms.

تظل الخدمات الجديدة غير الموجودة في الشيفرة الحالية، مثل تصنيع مؤقت أو عشائر أو سوق لاعب-إلى-لاعب، خارج قائمة الميزات العاملة حتى تُصمم وتُنفذ بقواعد ومحتوى حقيقيين؛ لا تستخدم بيانات تجريبية للإيحاء بأنها مكتملة.
